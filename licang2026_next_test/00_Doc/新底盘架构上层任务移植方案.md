## 1. 架构

流程以 Mission 为主线，一次只执行一个阶段：

```text
mission_app下发阶段命令
-> 底盘执行自己的路线
-> 底盘返回就绪/暂停/完成
-> mission_app确认状态后执行抓取或进入下一阶段
```

两个任务使用两个单向队列：

```text
mission_app -> chassis_command_queue -> 底盘任务
底盘任务   -> mission_event_queue   -> mission_app
```

每个队列只有一个消费者。任务空闲时阻塞等待消息，不需要反复空转读取。

## 2. 公共消息

双方共同包含 `chassis_mission_link.h`，不再各自复制枚举。

每条消息只有三个字段：

```c
uint16_t request_id;
uint8_t  type;
uint8_t  is_ready;
```

- `request_id`：标记本次流程，底盘回复时原样带回。
- `type`：说明当前命令或底盘位置。
- `is_ready`：`1` 表示成功/已经就绪，`0` 表示失败/未就绪。

消息不发送坐标、速度和移动时间。所有底盘参数继续放在底盘代码内部。

## 3. 双方职责

底盘任务负责：

- 四轮、IMU、灰度、地图和 `csvc` 初始化。
- 起点到圆盘。
- 圆盘到阶梯并对齐。
- 阶梯低、高、中三段横移。
- 收到识别停车请求后真正停车，再通知 Mission。
- 抓取完成后继续剩余横移。

Mission 任务负责：

- 红/蓝任务和总流程。
- Nano 圆盘/阶梯模式切换。
- 动作组 10～17。
- 圆盘 5 球、阶梯最多 2 球。
- IC、车载转盘、PB0 和球档案。
- 超时与安全停止。

## 4. 初始化

```text
底盘初始化完成 -> CHASSIS_CMD_MISSION_READY
Mission初始化和动作组10完成 -> MISSION_CMD_MISSION_READY
双方都READY -> 允许开始正式任务
```

任一方未准备好时都不能启动底盘。

## 5. 圆盘流程

```text
Mission -> MISSION_CMD_GO_PLATFORM
底盘完成导航、找线和停车
底盘 -> CHASSIS_CMD_PLATFORM_READY
Mission确认 request_id 一致且 is_ready=1
Mission执行动作组11，再开始圆盘抓取
```

圆盘任何一次抓球前，都必须已经收到 `CHASSIS_CMD_PLATFORM_READY` 的成功消息；未收到、`is_ready=0` 或超时，不能执行动作组 11/12。

圆盘前 4 球固定执行：

```text
动作组11识别
-> Nano识别目标球
-> 动作组12抓取并存入车载转盘
-> IC最多读取5次
-> 保存球档案
-> 车载转盘进入下一槽
-> PB0微调
-> 回动作组11
```

圆盘第 5 球执行：

```text
动作组12抓取
-> 动作组17将小球安全送入下一格
-> IC最多读取5次
-> 保存球档案
-> 车载转盘进入下一槽
-> PB0微调
-> 动作组10返回底盘移动安全姿态
-> Mission发送MISSION_CMD_GO_STAIRS
```

动作组17只用于圆盘第5球。动作组17、存球子流程或动作组10任一步骤失败或超时，都不能发送`MISSION_CMD_GO_STAIRS`。

圆盘结束后：

```text
Mission -> MISSION_CMD_GO_STAIRS
底盘到阶梯并完成找线对齐
底盘 -> CHASSIS_CMD_STAIRS_READY
Mission确认 request_id 一致且 is_ready=1
```

## 6. 阶梯流程

阶梯顺序固定：

```text
低 -> 高 -> 中
```

进入某层时：

```text
底盘 -> CHASSIS_CMD_STAIR_LOW/HIGH/MID
Mission确认机械臂和Nano视觉准备完成
Mission -> MISSION_CMD_CAM_READY
底盘开始本层横移
```

`CHASSIS_CMD_STAIR_LOW/HIGH/MID` 是底盘对当前层起点的状态通知。Mission 只有收到对应层通知且 `is_ready=1` 后，才发送 `MISSION_CMD_CAM_READY`；底盘收到该命令后才允许开始横移。

横移中识别到球：

```text
Mission -> MISSION_CMD_STAIR_STOP
底盘实际停车
底盘 -> CHASSIS_CMD_STAIR_PAUSE
Mission确认 request_id 一致且 is_ready=1
Mission才执行14/15/16抓取
Mission执行动作组13恢复识别姿态
Mission执行IC、球档案、转盘和PB0修正
Mission -> MISSION_CMD_STAIR_RESUME
底盘恢复剩余横移
底盘 -> CHASSIS_CMD_STAIR_RESUME
```

阶梯抓球前的“查询底盘状态”就是等待 `CHASSIS_CMD_STAIR_PAUSE` 成功回报，不是收到视觉事件后立即执行抓取。`is_ready=1` 表示底盘已经实际停车，可以让机械臂进入抓取动作；失败或超时必须停止本次抓取流程。

一层完整走完后，底盘通知下一层就绪。中层走完后发送：

```text
CHASSIS_CMD_STAIRS_FINISHED
```

规则：

- 动作组 13 是统一识别姿态。
- 14、15、16 分别为低、高、中抓取。
- 未抓球时不重复执行动作组 13。
- 抓到球后回 13，再继续本层剩余路程。
- 本层必须走完才能进入下一层。
- 抓满 2 球后不再触发抓取，但仍走完整个阶梯路径。

## 7. 请求编号

不做复杂并发。一次大阶段使用一个非零 `request_id`：

- 去圆盘使用一个编号。
- 去阶梯和整个低、高、中流程使用一个编号。
- 底盘回复时带回相同编号。

Mission 只处理“当前状态允许、编号一致且 `is_ready=1`”的成功消息，上一阶段迟到的消息直接忽略。`is_ready=0` 只能进入失败/停止分支，不能作为抓球放行条件。

## 8. 停止

```text
Mission -> MISSION_CMD_STOP
底盘立即停止当前运动
底盘 -> CHASSIS_CMD_STOPPED
```

STOP 不能等普通路线完整执行后再处理。底盘横移和导航等待过程必须能检查停止请求。

## 9. 容错保持不变

以下情况记录后继续：

- IC 每球最多读 5 次，仍失败则写 `READ_FAILED` 后继续。
- PB0 达到最大修正次数仍失败，记录后继续。

以下情况停止任务：

- 底盘、ZDT、机械臂或 Nano 通信/协议/超时错误。
- ZDT 堵转、保护或掉电。
- 用户 STOP。

IC pending 容量为 1 只是限制同时未完成的请求数，不是把 5 次重试改成 1 次。

Mission任务使用线程标志等待事件：

```text
底盘事件：先写 mission_event_queue，再设置 CHASSIS_MISSION_FLAG_EVENT
用户命令：写 Mission 私有 command_queue，再设置命令标志
视觉/存球结果：各自Device直接回调Mission内部处理，不保留外部notify占位接口
```

线程标志只负责唤醒，具体底盘消息仍由队列保存；同一类视觉触发重复到达时由当前状态过滤。Mission直接使用Nano协议Core和`mult_uart_device_submit()`，不再增加Nano adapter文件。

Mission不再同时保存`state + flow`，也不保存重复的姿态就绪、层就绪和恢复标志。当前上下文只保留：

```text
RTOS任务/命令队列
设备操作接口及其少量异步传输邮箱
当前线性状态、颜色、阶梯层
当前request_id和超时
圆盘球数、阶梯球数、物理槽位和球档案
故障和初始化状态
```

动作组和设备结果是否有效直接由当前线性状态判断。线程标志只负责唤醒；视觉帧、IC结果和ZDT响应在回调中复制到静态邮箱，再由Mission任务串行解释。

## 15. 给底盘侧的实现接口

底盘侧只需包含 `chassis_mission_link.h` 并实现下面的行为：

1. `chassis_mission_link_init()` 已由F7装配调用，底盘读取 `chassis_command_queue`。
2. 收到 `MISSION_CMD_GO_PLATFORM/GO_STAIRS` 后执行内部路线，完成后向 `mission_event_queue` 投递对应 `CHASSIS_CMD_*_READY`。
3. 收到 `MISSION_CMD_CAM_READY` 后才开始当前低/高/中层横移。
4. 收到 `MISSION_CMD_STAIR_STOP` 后实际停车，再投递 `CHASSIS_CMD_STAIR_PAUSE`。
5. 收到 `MISSION_CMD_STAIR_RESUME` 后继续剩余横移，再投递 `CHASSIS_CMD_STAIR_RESUME`。
6. 中层走完投递 `CHASSIS_CMD_STAIRS_FINISHED`；收到 `MISSION_CMD_STOP` 后停车并投递 `CHASSIS_CMD_STOPPED`。
7. 所有回包原样携带命令的 `request_id`，失败时 `is_ready=0`。

底盘侧不需要创建第二套Mission状态机，也不需要实现视觉、机械臂、IC或转盘接口。
