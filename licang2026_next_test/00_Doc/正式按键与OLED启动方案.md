# 正式按键与LED启动方案（取代OLED方案）

更新：2026-10-15，PD15红方备用选择见第六节；原LED实测记录属于旧版本，当前BASE=0现场问题仍未定位。

原版日期：2026-10-12。状态：代码已接入，用户反馈红蓝两边实机测试可行（2026-10-12）；异常场景未逐项宣称已通过。沿用原文档路径便于查找，不再使用OLED。接入前现场版本已本地提交d692877。

## 一、目标和操作方法

用户上电后选择红蓝方，等待PE11就绪灯亮，再按KEY1。系统锁定颜色，确认后至少等待1秒，且启动握手成功后出发。取消原4秒自动出发。

PE11亮的准确含义是：整机启动所需的基础准备都已成功，现在可以按启动键。它必须同时包含Nano视觉通信及模型就绪、机械臂动作10完成、底盘基础初始化成功，不能只因视觉就绪就点亮。正常情况下，灯亮后无需再等模型加载或机械臂归位。

## 二、硬件定义

| 硬件 | 引脚 | 行为 |
|---|---|---|
| KEY1 | PD13 | 低电平按下，确认启动 |
| KEY3 | PD12 | 松开/高电平选红方；按下/低电平选蓝方 |
| KEY4 | PD15 | 低电平选择红方备用，随KEY1确认锁定；与蓝方同时选择时拒绝启动 |
| 未确认输入 | PD14 | 不绑定功能 |
| 整机就绪LED | PE11 | 低电平点亮，高电平熄灭 |
| 颜色LED | PE12 | 低电平亮为蓝方，高电平灭为红方 |

LED使用普通GPIO推挽输出、Low速度、NOPULL，上电先置高保持熄灭，同步代码与CubeMX `.ioc`。LED接线应带限流电阻并满足板端电压要求。PE11/PE12不再作为软件I2C使用，不允许OLED驱动继续操作这两脚。

按键保持已确认的低电平有效方式，不擅自改变输入上下拉。约50ms稳定后采纳电平；颜色默认红方，上电读到稳定低电平KEY3后显示蓝方。此方案不再有“未选择颜色”、双键选色或KEY4启动。

## 三、整机就绪条件

出发前PE11仅在以下条件全部满足时点亮：

1. STM32通过现有模型查询协议收到Nano有效的“模型就绪”回复；仅服务已启动、串口收到数据或SESSION_READY不足以替代此条件。
2. 机械臂动作组10收到成功完成回报，不能只以命令发送成功判断。
3. 底盘基础初始化成功，原四轮电机通信就绪等启动条件已通过。
4. Mission不存在阻止启动的故障，相关初始化没有报告失败。

就绪灯不能用固定等待时间代替真实条件。等待期间继续处理Nano回包、机械臂完成回报及底盘事件。

启动前若已知条件失效或出现故障，灯熄灭且拒绝启动。现有模型就绪标志是否锁存、如何接收故障以实际协议为准，不把本次方案扩展为新的Nano在线心跳系统；已有协议未检测到的断线不能承诺由灯实时反映。

## 四、初始化与底盘握手的拆分

现有底盘app_task先等待颜色，再side_apply加载地图/设置起点，再link_handshake。Mission现有mission_try_ready成功后进入约4秒自动出发倒计时。

新方案保留电机、底盘服务、机械臂动作10和Nano模型查询的原初始化顺序，仅将底盘启动准备明确分成两步：

- 基础就绪：底盘成功初始化后，在等待颜色之前向Mission发布可靠的就绪反馈，用于PE11灯及KEY1门控。
- 颜色确认后的任务握手：KEY1锁定本轮颜色后，底盘加载对应地图、设置起点，再完成原Mission任务握手，随后等待GO_PLATFORM。

基础就绪反馈应复用现有通信/事件方式，具体接口在实施前核对，不以任务创建成功或经过固定延时冒充。不能要求选色后的任务握手完成才允许按KEY1，否则底盘等颜色而Mission等握手，会形成互等。

因此灯亮表示可以按KEY1完成启动操作，但地图设置及最终任务握手仍在按下后执行；正常情况自动衔接，无需用户再按一次。若这一步失败，必须拦截出发并报告原因，不能为保证“一按就跑”跳过检查。

## 五、状态流程

### 1. 上电准备

- PE11灭；PE12根据消抖后的KEY3候选颜色显示。
- 保持Nano模型查询、机械臂动作10、电机通信和底盘初始化。
- 候选颜色与实际g_mission_side分离，实际颜色先保持NONE，不让底盘提前使用尚未确认的颜色。
- KEY1未就绪时的按下无效、不缓存；提前按住不会在灯亮瞬间自动启动。

### 2. 可以启动

- 全部基础准备满足，PE11亮。
- KEY3仍可修改候选颜色，PE12跟随显示。
- KEY1须在就绪后经历稳定松开再稳定按下，接受一次启动请求。若在就绪时已经松开，之后正常按下即可。
- KEY1确认时KEY3应已稳定；KEY3仍在抖动时拒绝该次确认并提示重新按，不锁定模糊颜色。

### 3. 确认与1秒等待

- KEY1有效按下时锁定颜色并发布g_mission_side，记录确认时间。
- 底盘按锁定颜色设置地图和起点，完成原有任务握手；重复按键不重复提交。
- 使用非阻塞状态机计时，继续处理所有通信、完成回报和故障；禁止用阻塞delay等待1秒。
- 出发必须同时满足：启动已确认、无启动故障、基础准备有效、颜色相关初始化成功、最终任务握手完成、确认后已满1000ms。
- 握手快则等满1秒；握手慢则等待成功后再出发，不要求严格恰好1秒。原4秒倒计时取消，不叠加。
- 确认后颜色锁定，1秒期间再改变KEY3不改变本轮颜色。PE12保持锁定颜色。
- 已知启动故障时PE11熄灭，不自动重试出发。地图/起点失败必须显式传回Mission，不能只在底盘日志中报错却显示已就绪并发送GO_PLATFORM。

### 4. 正式运行

- 仅发送一次GO_PLATFORM，进入原比赛流程。
- 停止按钮扫描、按钮电平日志和LED刷新，两灯保持出发时的状态。
- PE11运行后不再作为实时视觉在线或故障指示灯；原故障停车与通信保护继续有效。
- 运行中KEY1、KEY3、KEY4变化不影响本轮；故障后不自动重新启用按键启动，不意外重跑。

## 六、KEY4红方备用选择（已接入）

KEY4/PD15低电平选择红方备用，KEY1有效确认时与KEY3颜色一起消抖并锁定。红方+PD15进入圆盘机后直达仓库的独立模式；蓝方+PD15明确拒绝，释放KEY1后再确认；PD15松开继续原正式流程。运行中不触发任何备用动作或切换。完整实现、独立参数和实机边界见《红方备用模式与现场调参.md》。

## 七、日志设计

- 保留必要启动事件日志：等待缺项、整机就绪、KEY1拒绝原因、锁定颜色、等待最终握手、GO_PLATFORM发出。
- 等待日志限频，明确ARM10、MODEL、CHASSIS_BASE、FAULT状态，用户可看出慢在视觉还是其他设备。
- 原四路按钮原始电平日志在本方案落地后不持续刷屏；运行开始后停止按键诊断。
- 不更改既有视觉、机械臂、仓库和故障日志的含义。

## 八、修改范围和保护边界

1. Mission：按键消抖、候选与锁定颜色、基础就绪判断、LED显示、1秒计时、替换自动启动分支及出发后关闭交互。
2. 底盘启动入口与现有接口：增加基础就绪反馈，保留选色后的side_apply及最终任务握手，补齐启动失败反馈；不改运动阶段逻辑。
3. GPIO与.ioc：PE11/PE12改LED输出，初始化高电平。
4. 默认启动任务：撤下OLED等待500ms、初始化、刷新、诊断快照及其他运行路径中的OLED调用；基础硬件初始化本身按依赖检查后处理，避免误伤其他外设。OLED源文件和历史资料先保留，不删除或移动。
5. 正式模式改为实体按钮启动；无线测试仍按原指令方式工作，不将实体按钮混入其控制流程，也不能让无线分支继续把PE11/PE12当OLED使用。
6. Nano代码、模型、协议字段、UART复用、ACK、视觉会话、动作完成回报、原通信超时、运动路线、速度、仓库校准及故障停车保持。
7. 实施前复查g_mission_side为NONE的消费者、启动标志的生命周期、队列顺序与实际READY分支，避免初始化互等或重复出发。

## 九、验证要求

- 编译及差异检查；确认PE11/PE12不存在OLED残留读写，原运动/视觉代码未被无关修改。
- Nano未启动、模型加载慢、动作10未完成、底盘未就绪分别验证：PE11必须灭，KEY1无效且不缓存。
- 全部准备完成PE11才亮；提前按住KEY1不误启动，松开重按正常。
- KEY3松开：红方/PE12灭；KEY3按下：蓝方/PE12亮。确认颜色灯、Mission目标色和底盘地图一致。
- KEY1确认到GO_PLATFORM至少1秒，不再有原4秒等待；慢握手、失败握手不能按时间强制出发。
- 确认后切色或重复按KEY1不重复出发；PD14无功能；红方+KEY4选择备用，蓝方+KEY4拒绝启动。
- 出发后按钮与LED更新停止，改变开关不影响正式流程。
- 分别验证红蓝启动，再验证正式全流程。编译验证与实机通过分别记录。

## 十、版本状态

本地恢复点f2a6f48保存此前配置与现场路线/角度参数；之后还有OLED诊断、软件I2C、GPIO生成和按钮日志等未提交变化，不能称该提交等于当前工作区。实施前核对真实Git并按用户要求保存，不覆盖用户修改。

当前已撤下OLED启动调用及500ms等待；正式启动已改KEY1确认，PE11/PE12为推挽输出、高电平熄灭。新增底盘基础就绪队列事件CHASSIS_CMD_BASE_READY（追加编号，不改变旧事件编号）；实际最终握手失败仍禁止出发，KEY1确认后的握手保护上限沿用MISSION_OPERATION_TIMEOUT_MS=30000ms。

主机测试使用实际Mission启动函数配合GPIO和时钟替身，覆盖未就绪拒绝、提前按住、消抖、红蓝选择、确认后锁定、快慢握手计时、故障及出发后不更新。主机通过不能替代板上握手、LED接线和红蓝正式流程验证。
