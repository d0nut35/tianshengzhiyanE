# Flash容量优化执行规范

## 1. 目标与顺序

在保持现有功能和安全边界的前提下逐层减少正式固件Flash占用。

执行顺序：

1. 光电门
2. LSC16机械臂
3. mult_uart串口复用
4. IC读卡器
5. ZDT转盘电机
6. Nano视觉

一个模块完成后停止，报告结果并询问是否进入下一个模块。

## 2. 分步原则

完整分层模块按以下三部分处理，每部分单独构建和本地提交：

1. Core合入HAL BSP：固定STM32 HAL、UART和DMA，删除端口函数表及适配上下文。
2. OS合入Service：Service直接使用CMSIS-RTOS2/FreeRTOS，删除OS适配函数表和重复包装。
3. Device合入Service：删除提交函数指针、桥接函数和重复状态，同步修改App/Mission调用。

缺少某一层的模块按真实结构处理。没有代码变化或容量收益时不制造提交。

## 3. 接口命名

- 使用简短且明确的模块前缀：`gate_`、`arm_`、`mux_`、`ic_`、`turn_`、`vision_`。
- 删除已经不存在的`_device`、`_service_os`、`_stm32_hal`等层级后缀。
- 不使用含义不清的单字母或过度缩写。
- 详细职责、参数单位和异步语义写入Doxygen注释。
- 不保留只为兼容旧函数名而增加的转发包装。
- 保留业务完成回调、`user_ctx`和原始`request_id`。

## 4. 必须保留

- `uart_dispatch`统一拥有HAL UART全局回调。
- 模块回调先过滤UART句柄。
- DMA缓冲区在传输完成或中止前保持有效。
- ISR只记录事件或搬运数据，协议解析和业务回调留在任务上下文。
- 队列容量检查、事务超时、UART/DMA中止和接收恢复。
- ZDT状态轮询、STOP和光电门到位判断。
- IC读卡重试、视觉会话校验和Mission机械停止保护。

## 5. 启动失败

公共安全入口使用短名称：

```c
/** 关闭机械输出和通信驱动；幂等且不依赖RTOS运行。 */
void sys_safe(void);
```

不可恢复的软件模块启动失败统一处理：

```c
if (xxx_init() != OK) {
    sys_safe();
    Error_Handler();
}
```

`sys_safe()`只做确定性的停止和禁用操作：阻止新动作、中止在途通信、停止可用机械对象并禁用复用器输出。不得删除任务、队列或对象，不尝试重新初始化。

基础时钟、GPIO或DMA尚未完成初始化时直接调用`Error_Handler()`。运行阶段错误继续使用原有超时、恢复、重试和故障停车流程。

## 6. Keil工程

- 分组与实际源码目录一致，接近VS Code文件树。
- 每次同步删除已合并或已删除文件的工程条目。
- 正式工程只显示正式构建需要的源码和必要头文件。
- `05_Test`、host fake和未启用的直连测试保留在仓库，不放入正式Keil工程。
- 删除未参与链接的工程条目不得计入Flash节省量。

## 7. 构建与提交

每个部分严格执行：

1. 记录上一个提交的`.map`基线。
2. 只修改当前部分及必要调用方、测试引用和Keil条目。
3. 完整执行Keil Rebuild。
4. 核对`0 Error(s), 0 Warning(s)`及关键对象、符号。
5. 比较`Code`、`RO-data`、`RW-data`、`ZI-data`、`LR_IROM1`和剩余Flash。
6. 只有功能边界清楚且容量未增加时才创建一次本地提交。
7. 提交标题使用简短中文，提交正文记录真实`.map`差值。
8. 提交后立即报告；模块完成后等待确认再进入下一模块。

提交正文格式：

```text
Map: LR_IROM1 <before> -> <after> B (<delta> B)
Code: <before> -> <after> B (<delta> B)
RO/RW/ZI: <before> -> <after>
Flash free: <before> -> <after> B
Build: 0 Error(s), 0 Warning(s)
```

## 8. 停止条件

出现以下任一情况时停止当前部分，不提交并报告：

- Flash占用增加且没有必要的安全或功能收益。
- 无法证明异步回调、DMA生命周期或`request_id`保持正确。
- 需要改变已实机验证的协议、时序或机械保护。
- 构建存在错误、警告或关键符号异常。
