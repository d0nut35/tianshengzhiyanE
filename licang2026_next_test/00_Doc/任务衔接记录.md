- 正式工程：`D:\programfile\project\licang2026v1`，MCU为STM32F750V8Tx。

## 3. UART8 LSC16机械臂舵控

### 文档确认的协议事实

- UART通信参数为9600、8N1。
- 帧格式为`55 55 Length Cmd Parameters`，`Length`为参数长度加2。
- 单/多舵机运动命令为`0x03`，运行动作组为`0x06`。
- 动作组开始、强制停止和自然结束分别回传`0x06`、`0x07`、`0x08`。
- 协议文档没有规定单舵机`0x03`命令的成功应答，因此只能把UART异步TX完成记为“帧已交给UART发送”，不能据此判断舵机已经执行。

### 工程中已实现

- 协议Core：`03_Middleware/lsc16/lsc16_core.h/.c`，不依赖HAL和FreeRTOS。
- F7 HAL adapter：`04_Bsp/lsc16/lsc16_stm32_hal.h/.c`。
- 平台无关Service和CMSIS-RTOS2 worker：`02_Service/lsc16`。
- Device语义接口：`01_App/lsc16_device`。
- 裸机与FreeRTOS测试：`05_Test/lsc16`。两种测试上电后只等待USART1文本命令，不自动发送运动；电脑可发送`SERVO/ACTION/STOP/BATTERY/STATUS`，并直接读取发送完成、板端回报和计数文本，不再依赖Keil Watch。
- `00_Doc/LSC16_USART1命令测试说明.md`记录UART8/USART1接线、运动锁、命令、预期现象和安全实验顺序。
- UART8为PE0 RX、PE1 TX、9600 8N1；TX使用`HAL_UART_Transmit_IT()`异步中断发送，RX使用DMA1 Stream6。
- UART8使用ReceiveToIdle；用户已在CubeMX启用UART8全局中断并重新生成，IRQ优先级为5，`.ioc`、`usart.c`和`stm32f7xx_it.c/.h`已核对一致。
- 2026-08-25已在测试分支释放UART7 TX使用的DMA1 Stream1和UART8 TX使用的DMA1 Stream0；当前CubeMX仅保留UART7_RX Stream3、UART8_RX Stream6和USART1_RX DMA2 Stream2，Stream0/1留给底盘分支后续配置。
- LSC16通过公共`uart_dispatch`认领UART8事件，不再定义独立HAL全局回调。

### 已完成的软件验证

- LSC16 Core和Service的PC fake测试通过。
- 单舵机和动作组示例帧与协议文档一致。
- F7 ArmClang源码检查通过。
- CubeMX重新生成后执行Keil完整构建，结果为`0 Error(s), 0 Warning(s)`，AXF和HEX已生成。

### 安全配置与当前现场

- 正式发布配置仍应恢复`LICANG_ACTIVE_TEST=LICANG_TEST_NONE`；当前实际`05_Test/test_config.h`选择`LICANG_TEST_LSC16_FREERTOS`。
- 当前`LSC16_TEST_MOTION_ARMED=0`，即使电脑发送`SERVO/ACTION`也不会下发运动帧。
- 用户指定200号为安全测试动作组，当前`LSC16_TEST_ACTION_GROUP=200`、重复1次；这只是测试参数配置，必须先确认动作组已经下载到当前舵控板且机械范围安全，不能记作实机验证。
- 用户决定本轮先测FreeRTOS，若出现问题再切换裸机路径隔离。

### 明确未完成的硬件验证

- 没有下载运行FreeRTOS测试。

- 没有确认200号动作组在当前舵控板上的实际动作，以及真实板上`0x06/0x08`回传。

## 4. IC读卡器（UART7直连封装与复用通道1）

### 文档确认与规则边界

- 模块为M2940B-HA，厂家默认地址0x20、默认9600 8N1；此前厂家上位机已在115200下成功读UID，因此当前这块实物曾被配置为115200。
- 命令帧为`[类型][总长度][命令][地址][参数...][校验]`，校验为前序字节逐字节异或后按位取反，协议没有固定帧头。
- A3使用读卡器内部保存的Key A读取数据块；当前比赛读取0扇区块1。Key A尚未由正式比赛样球确认。
- 2026初步规则已取消二维码和干扰球。球数据16字节应完全一致，高半字节表示1~3行，低半字节表示1~4列；`0x14`当前表示第1行第4列。2025规则中“0x14为干扰球”的旧结论只适用于往年规则。

### 工程中已实现

- `03_Middleware/ic_card/ic_card_core.h/.c`：平台无关协议Core，支持A3、B0/B1/B2/B8、DMA分包/粘包解析、坏帧过滤和错误恢复。
- `04_Bsp/ic_card`：只保留UART7直连HAL adapter；2026球值解释位于`01_App/ic_card_device/ic_ball_rule_2026.*`，避免比赛规则污染通用协议。
- `02_Service/ic_card`：静态队列、单在途事务、响应匹配、500ms超时和CMSIS-RTOS2 worker。
- `01_App/ic_card_device`：比赛球语义接口，成功时返回16字节、编码、行和列。
- `05_Test/common`：测试专用USART1调试命令ReceiveToIdle DMA接收和纯文本输出。
- `05_Test/ic_card`：裸机和FreeRTOS两套UART7直连测试，均以USART1的`BALL_READY`/`READ`触发一次读卡；测试默认关闭。
- `05_Test/host/<module>`：Core、Service和规则fake测试以及统一运行脚本；不加入Keil目标。
- `00_Doc/IC卡_UART7直连测试说明.md`：接线、模块建议参数、开关、串口命令、结果解释和复用接入边界。

### 配置与验证状态

- 用户已配置并重新生成：UART7 PE7/PE8、115200、TX中断发送、RX DMA1 Stream3和全局IRQ；USART1 PA9/PA10、115200、RX DMA2 Stream2和全局IRQ；PB1为`IC_CARD_IO`输入。工程已核对一致。
- IC Core和Service fake测试通过。
- Keil分别验证默认关闭、IC裸机、IC FreeRTOS三种模式，均为0 Error、0 Warning；随后曾切换为复用模块FreeRTOS集成测试并完成通道1实测，当前活动场景已改为LSC16 FreeRTOS。
- 修复了ArmClang 6下旧CubeMX FreeRTOS模板未声明`SystemCoreClock`而导致`cmsis_os2.c/port.c`编译失败的问题。

### 推荐设置、实机验证与未验证项

- 当前比赛建议用命令模式；球放稳后F7主动发送一次A3。建议维持当前115200、8N1和地址0x20，读取块1。
- 自动上传/连续读取不作为转盘推进依据；PB1只作为可选提示输入，不能代替UART球值解析。
- UART7复用通道1 transport已通过真实F7的A3读球：成功得到`0x11`、`0x12`等16字节一致数据并解析行列。供电不稳时出现过`IC READ ERROR 10`，供电恢复后重新成功读取。
- UART7直连裸机/FreeRTOS测试未做；当前把它保留为复用链路异常时的诊断工具，不再作为进入任务流程的强制前置。
- Key A最终比赛样球确认、读卡距离/姿态、无球超时恢复、连续球流程和PB1电平时序仍待最终机械结构验收。

结论：IC卡“分层驱动、软件/编译验证和UART7复用通道1真实比赛球读取已经通过”；“直连两套测试、PB1以及最终机械容差”仍未验证。

## 5. ZDT_X42S转盘电机（UART7直连与复用通道2）

### 文档确认和实物固件

- 重新核对`ZDT_X42S第二代闭环步进电机使用说明书V1.0.2_251118.pdf`；小屏幕第二行显示`0.00err`是Emm固件界面格式，不是本次通信错误码。
- X与Emm固件都使用`0xFD`位置命令，但字段、速度Scale和角度表示不同，构帧前必须先读OPTIONS确认固件。
- 实机OPTIONS原始帧为`01 1A 00 06 6B`；16位标志`0x0006`表示1.8度电机、Emm固件、闭环、CW正方向、Scale关闭。

### 工程中已实现及协议修正

- `03_Middleware/zdt_turntable`：X/Emm平台无关协议Core；`04_Bsp/zdt_turntable`：UART7直连STM32 HAL adapter。
- `02_Service/zdt_turntable`：单在途事务、响应匹配、超时和CMSIS-RTOS2 worker；`01_App/zdt_turntable_device`：版本、选项、状态、位置、停止和固定角度运动语义接口。
- `05_Test/zdt_turntable`：通过USART1文本命令执行裸机/FreeRTOS直连测试；ZDT模块不定义HAL全局回调，而是向`uart_dispatch`注册UART7句柄过滤handler。
- OPTIONS严格按5字节响应解析16位标志，补齐MotType、FwType、CtrMode、MotDir、BtLock、Scale和参数锁等级。
- STATUS优先识别`E2/EE`错误帧，补左右限位及掉电锁存；查询响应不再误接受动作ACK，绝对零位置和零脉冲合法。
- 正确处理X角度Scale、Emm速度Scale；Emm角度转脉冲使用安全四舍五入和溢出检查。
- 已补充职责、状态变化、异常恢复、完整单帧接收、缓冲区生命周期和STOP非硬件急停等中文Doxygen注释。

### 软件和编译验证

- `zdt_turntable_core`、`zdt_turntable_service`、`zdt_turntable_device`三套PC fake测试全部通过。
- ZDT裸机与FreeRTOS两种Keil完整构建均为`0 Error(s), 0 Warning(s)`；最终AXF保持ZDT FreeRTOS目标供当前实机测试。

### 实机验证与当前现场

- UART7直接连接电机、不经过复用板，已得到：`VERSION FW=201 HW_SERIES=2 HW_TYPE=3 HW_VER=20`。
- OPTIONS原始帧为`01 1A 00 06 6B`；STATUS为`ENABLE=1 REACHED=1 STALL=0 PROTECT=0 POWERLOSS=0`；POSITION为`SIGN=+ RAW=3`。
- ZDT集成实测阶段使用过`LICANG_TEST_MULT_UART_MODULES_FREERTOS`和专用运动锁1；该阶段烧录后不自动运动，仅USART1命令驱动转盘。当前活动场景已改为`LICANG_TEST_LSC16_FREERTOS`，此条只保留为ZDT实测历史配置。
