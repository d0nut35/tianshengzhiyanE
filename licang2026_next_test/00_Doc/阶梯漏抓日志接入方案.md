# 阶梯漏抓：STM32与Nano日志接入方案

日期：2026-10-08。状态：用户确认后已实施两端日志代码，默认关闭；PC验证完成，尚未烧录或更新Nano现场服务。启用及字段说明见同目录《阶梯漏抓日志使用说明.md》。下面保留已确认的接入范围与验证要求。

## 1. 目标与现状

目标是在完整比赛流程中定位“阶梯有时一个球都不抓”：没有有效视觉候选、候选被过滤、没有发送事件、STM32拒收事件、停车/动作回报不匹配，或抓取后读卡/入仓异常。

以当前源码为准：阶梯顺序为LOW→HIGH→MID，对应Nano场景2/3/4；识别姿态13，抓取动作14/15/16，抓取完成后回13读卡入仓；阶梯结束停视觉，18→10完成后前往小圆盘。现有阶梯累计上限为2，达到上限后仍走完剩余层，但不再开视觉。

STM32已有Mission状态、故障、底盘收包、机械臂发送/完成、视觉START/READY/ACK等日志。通用视觉接收日志目前偏向仓库，不能解释阶梯事件被丢弃的原因。底盘app_stairs.c的少量ST_LOG受APP_LOG_EN控制，主要记录层完成和运动错误，也不能解释视觉漏抓。

Nano已有SESSION READY/STOPPED、EVENT SEND/RETRY/ACK/TIMEOUT和部分相机错误输出。--log-polls作用于旧POLL分支，正式SESSION流程不能靠这个参数得到候选过滤和未发事件原因。

## 2. 开关与查看方式

STM32沿用现有MISSION_DEPOT_TRACE_ENABLED，不新增诊断宏。它目前只在正式模式生效，正式诊断固件的组合为：

```c
#define MISSION_CHASSIS_ROUTE_TEST_ENABLED  0U
#define MISSION_DEPOT_TRACE_ENABLED          1U
```

输出仍走USART1原有日志口，新增阶梯行使用[S]前缀。关闭时TRACE=0；无线联调模式ROUTE_TEST=1维持原有行为。仅修改原宏注释，让它说明包含正式仓库和阶梯诊断。

Nano增加--stair-debug，默认关闭，只对阶梯场景2/3/4启用新增细节。因此完整流程可以看到日志，无需改用单独视觉预览，也无需改成POLL协议。

现场启用前先检查实际服务：

```sh
systemctl cat licang-nano-vision.service
```

在实际ExecStart原有参数末尾追加--stair-debug，保留解释器、串口、相机和完整数据模型的所有现有参数。修改服务后在静止状态重新加载并重启：

```sh
sudo systemctl daemon-reload
sudo systemctl restart licang-nano-vision.service
journalctl -u licang-nano-vision.service -f -o cat
```

这些是实施后的操作说明，本次未修改或重启Nano现场服务。若当前以终端手动启动，就在原启动命令追加参数，直接看该终端。运行中只保留一个相机/串口服务实例。

## 3. STM32新增内容

日志在Mission任务处理结果时输出，不在中断、UART回调、机械臂或底盘工作线程中打印。

| 环节 | 需要记录的内容 |
| --- | --- |
| 阶梯入口 | GO_STAIRS、request_id、STAIRS_READY接受或忽略原因、动作13发送及匹配完成；层事件提前到达时记录“已保存，等待13完成” |
| 分层与开会话 | LOW/HIGH/MID、实际协议scene=2/3/4、SID、目标颜色、当前计数；匹配READY后CAM_READY发送；旧层会话STOP/STOPPED后新START的顺序 |
| 视觉接收 | 解码结果、SID、scene、frame、status、color、age；接受事件记录一次，拒绝按具体原因累计，避免每包打印 |
| 拒绝原因 | 解码失败、SID不匹配、scene不匹配、状态无效、颜色不符、age超过当前120ms门限、Mission不在允许处理事件的状态；未解码成功的字段不能拿来打印 |
| 停车与ACK | 接受的SID/frame；ACK提交与实际发送完成分别记录；STAIR_STOP发送与匹配STAIR_PAUSE分别记录；只有停车确认且ACK完成后才进入抓取 |
| 抓取与回位 | 当前层映射14/15/16、发送、实际匹配完成或异常回报、回13完成；发送成功不记成动作完成 |
| 读卡与入仓 | IC每次重试序号和结果、有效记录或READ_FAILED、转盘目标槽及PB0到位、计数与槽位更新；内部槽号和物理槽号明确区分 |
| 恢复扫描 | 未满2次时新的SID/READY、STAIR_RESUME请求与确认；已满时明确SKIP_LIMIT，不再开视觉 |
| 阶梯结束 | STAIRS_FINISHED、视觉停止、18→10实际完成；汇总有效事件、抓取动作完成、有效IC记录、READ_FAILED、拒收原因和超时 |

现有stair_balls在入仓流程结束时递增，不能仅凭这个数证明机械上抓到了球；IC失败也可能走READ_FAILED建档分支。日志要分别显示动作完成、IC有效与入仓流程计数，不改变这些计数和容错规则。

保留原通用日志；补充START的实际scene和阶梯上下文，避免通用KIND值被误看成协议层号。每个SID保留固定大小的诊断计数，约每1秒输出一次无事件/拒收汇总，并在会话结束时补一次终结汇总，覆盖短会话。

## 4. Nano新增内容

修改nano_uart_vision_responder.py与Ball_C_v2.py。检测函数增加可选诊断统计参数，原调用方式和返回结构保持兼容；诊断关闭时不做新增统计。

| 环节 | 需要记录的内容 |
| --- | --- |
| 会话开始 | SID、scene、目标颜色、profile_generation，以及实际生效的HSV、形状阈值、ROI、稳定帧数等配置；每个新会话打印一次 |
| 相机与时效 | 新帧/读取超时次数、相机帧序号、读取时帧龄、处理耗时、结果总帧龄；沿用采集时间，不把处理结束时间当采集时间 |
| 颜色与形状 | 红蓝各自轮廓数、通过数；面积、周长、圆度、半径、填充率等现有过滤项的首次失败计数；未计算的指标显示None（即NA） |
| ROI与跟踪 | 形状候选数、ROI通过/拒绝、选中目标位置与面积；当前跟踪是否稳定、是否partial、是否缺少有效估计 |
| 发事件前 | 是否VALID、保护时间是否结束、是否采于本次START之后、是否为当前generation；记录实际阻止发送的条件，不新增业务门限 |
| 发送与确认 | SID/frame/scene/age、首次发送、重发、匹配ACK、ACK超时、STOP；结束时汇总事件数和未发事件原因 |

过滤统计在现有检测过程中采集，不重复识别、不额外读相机、不做截图/视频保存、不改变阈值或模型。候选指标只用已经算出的数据；按第一个真实失败条件计数，避免同一轮廓重复计为多个失败。

VisionWorker只维护有限计数和最新统计快照，不逐帧打印。快照带profile_generation，由串口主循环核对当前generation后绑定SID并输出，避免旧层统计串到新层。新SID重置统计，重复START同一会话不误清零；STOP/结束补汇总。旧generation丢弃记录为会话切换诊断，不能污染新会话的候选数量。

约每1秒打印1～2条统计，事件和错误按发生打印。新日志及时flush。输出放在串口关键处理之后，不能拖延READY、ACK或STOP响应。阶梯普通跟踪和快速模式的帧龄判据并不完全相同，应打印实际判定，不能声称Nano所有阶梯事件都已按120ms拒绝；STM32收到后仍按现有120ms门限判断。

## 5. 两边如何对照定位

用SID、实际scene与frame关联两端，request_id关联STM32底盘命令；时间使用各自单调时间/会话耗时，不直接相减两台设备的时钟。

| 看到的现象 | 下一处检查 |
| --- | --- |
| 没有STAIRS_READY/层事件，或被request_id/状态拒绝 | STM32入口、底盘回报与状态 |
| 有START，没有匹配READY | Nano收命令、场景配置、相机启动、UART回报 |
| READY正常，轮廓为0 | 颜色阈值、光照、实际画面；不能据此断言场上没有球 |
| 有轮廓但形状/ROI全拒绝 | 对应首个失败条件与实际生效配置 |
| 有候选但无EVENT | 跟踪稳定/partial、会话前帧、保护时间、generation切换 |
| Nano发送EVENT，STM32不接受 | 同SID/frame的解码、颜色、scene、帧龄和状态拒收原因 |
| 接受EVENT但没有抓取 | ACK完成、停车确认、动作发送和匹配完成回报 |
| 抓取动作完成但仓库缺球 | IC结果、READ_FAILED、槽位与PB0；结合实物判断是否空抓 |
| 后续层无视觉 | 是否累计达到2并进入SKIP_LIMIT，或发生故障/会话超时 |
