# 现场圆盘机转速适配ROI预案

2026-10-13：待现场观察后实施，当前没有修改参数。对象为开头圆盘机turntable，不是绕桩small_disc，也不是车上步进转盘。

## 基线与原理

本地config/hsv_thresholds_v2.json的fast_triggers.turntable：X150..380、Y150..440、min_area=3000、hold_ms=120。红蓝目前共用该ROI，无turntable颜色覆盖；现场需核对运行目录、配置路径及CLI覆盖。fast按目标色候选球心进入ROI并满足过滤触发，黄点不是必须到达的位置；120ms不是夹取前等待。球速与识别到实际夹取的总延迟共同决定提前量。

机械动作、相机和延迟不变时：转速更快需要更早触发，入口边界向来球方向扩；更慢需要更晚触发，入口边界沿运动方向收。以闭爪时球还没到或已经过去判定，不仅看IN。相对旧速度的触发位移可近似为Δp=-(v新-v旧)×总延迟，v为入口附近图像速度向量，仅为局部近似，不能直接把角速度换成像素。

| 图像中球心方向 | 提前触发 | 延后触发 |
| --- | --- | --- |
| 上→下 | y_min减小 | y_min增大 |
| 下→上 | y_max增大 | y_max减小 |
| 左→右 | x_min减小 | x_min增大 |
| 右→左 | x_max增大 | x_max减小 |

不能沿用阶梯或绕桩的进框方向。弧线/斜向运动先从[T]轨迹和现场视频确认实际控制入口的边；需同时满足X/Y入框，改变非控制边可能无效。

## 现场执行

1. 固定起点、机械姿态、动作时间；保存旧配置和Git，核对服务实际参数。先跑现有参数，确认方向和早晚；准确就不改。
2. 一次只调整入口边界3～5像素，其他三边保持。例如确认右→左且偏晚，可先x_max380→385；偏早则380→375。这是示例，不是默认批准的修改。
3. 保存从会话START到触发、ACK的[T]/[V]日志，记录首球与后续球、闭爪时相对球位置。连续测试几次，红蓝分别复核；共用ROI修改可能同时影响双方。
4. 只有首球异常时检查首帧是否已在框内；若已在框内，扩大框不保证改善，先检查启会话时机及起点。先不更改会话状态机。
5. 忽早忽晚时优先查反光导致的球心跳变、漏检、运动模糊、延迟抖动；ROI用于修正稳定偏差，不掩盖算法或负载故障。
6. 保持HSV、面积、黄点、运动帧保护和机械动作不变。若需红蓝分离覆盖或联动改时序，先说明方案再执行。
